# kart-physics C ABI smoke test (M4 + ABI v4 ordinary N₂O)

Minimal C99 consumer of the frozen C ABI (`include/kart_physics.h` +
the `kart_physics` cdylib). It first runs the ABI version self-check
(`kart_physics_abi_version()` must equal the header's `KP_ABI_VERSION`)
and then creates every engine through the negotiated handshake,
`kart_physics_create_v2(..., KP_ABI_VERSION)`: the library refuses a
version mismatch with NULL + `KP_ERR_ABI_VERSION` detail, and the
returned engine reads the full current state, parameter, and world layouts.
Current hosts also use `kart_physics_state_default_v2` and
`kart_physics_parameters_default_v2`, passing `KP_ABI_VERSION`.

Plain `kart_physics_create` and the two unsuffixed default writers are the
frozen v1 compatibility surface. A v1 engine translates exactly the
historical 6448-byte state (including its 4096-byte JSON slot), copies only
the 536-byte parameter block, and reads only the 80-byte vtable prefix. The
exact-size Rust regression test covers create/get/set/step/default operations;
`scripts/verify_kart_physics_ffi_smoke.py` also probes the semantic
degradation path.

The smoke then runs four scenarios and
prints every f64 as its IEEE-754 bit pattern:

1. The M4 flat scenario: 20 frames of 16 ms with the UP key against a
   flat ground plane implemented through the world vtable.
2. The ABI v2 RAIL-vtable scenario (2026-07-29 capability completion): a
   functional mock world serves the open-mapping v2 slots
   (`query_rail_contact`, `query_rail_entry_boundary`,
   `rail_query_contexts`, `rail_entry_contexts`, `sweep_point`) with the
   payloads recorded from the Python reference run; the engine must
   enter AND exit the RAIL domain over 40 frames (per-frame state is
   printed, and the binary exits non-zero otherwise).
3. The ABI v3 semantic-CTRL scenario: four 2 ms frames dispatch the
   drift action with LEFT steering, hold, and release, then compare the
   B08/B0C selector state bit-exactly with the Python authority. D1 maps
   this semantic API key to physical Shift in the captured CN client.
4. The ABI v4 `ITEM_USE` scenario: an item6 in fixed slot0 is consumed on
   the first rising edge, a held key does not consume twice, release clears
   the latch, and a second press against empty slots fails safe. The two-slot
   inventory, four gauge fields, boost state/timer, and new parameter tail
   are compared bit-exactly with Python. This semantic key maps to physical
   Ctrl; it is intentionally distinct from ABI `KP_KEY_CTRL` (drift).

## Build and run

No build.rs is involved; the cdylib is built by cargo and the C file by
any C99 compiler:

```bash
cd rust
CARGO_INCREMENTAL=0 CARGO_TARGET_DIR=/tmp/kart-rust-target cargo build -p kart-physics

cc -std=c99 -Wall -Wextra \
  -I rust/crates/kart-physics/include \
  rust/crates/kart-physics/examples/c_smoke/smoke.c \
  -L /tmp/kart-rust-target/debug -lkart_physics \
  -o /tmp/kart_ffi_smoke

# macOS (.dylib):
DYLD_LIBRARY_PATH=/tmp/kart-rust-target/debug /tmp/kart_ffi_smoke
# Linux (.so): LD_LIBRARY_PATH=/tmp/kart-rust-target/debug /tmp/kart_ffi_smoke
```

`scripts/verify_kart_physics_ffi_smoke.py` (repo root) runs exactly this
sequence and then asserts the printed bit patterns are identical to the
Python reference engine (`scripts/kartrider_vehicle_engine.py`) driven
through the same scenarios, including ITEM_USE, the per-frame RAIL cycle,
and the v1-host refusal path of the ABI handshake.

## Header regeneration

The header is generated by cbindgen 0.29.4 and checked in; regenerate
after any `src/ffi.rs` change:

```bash
cd rust/crates/kart-physics
cbindgen --config cbindgen.toml --crate kart-physics --output include/kart_physics.h
```

`ffi::tests::layout_is_stable` pins the current and historical byte counts;
`ffi::tests::ffi_v1_shim_uses_exact_state_and_parameter_buffers` allocates
buffers of exactly the v1 sizes, while
`ffi::tests::ffi_v3_translation_uses_exact_state_and_parameter_buffers`
uses exactly 67984-byte state and 592-byte parameter allocations. Any
intentional current layout change must
bump `KP_ABI_VERSION`; the v1 layout and unsuffixed entry points remain
frozen.
